# Сайт-портфолио (GitHub Pages)

Одностраничный сайт-портфолио в композиции шаблона
[Knuford (Colorlib)](https://preview.colorlib.com/theme/knuford/), но написанный
с нуля на Bootstrap 5: без jQuery, без чужой CSS-темы, со своими токенами
палитры и типографики.

Секции: hero → обо мне → навыки → опыт → работы → услуги → контакты (форма) → футер.
Сознательно не добавлены секции «Отзывы», «Блог» и «Цены»: в шаблоне они
заполнены выдуманными данными, а пустая секция честнее фейковой.
Как вернуть — ниже.

## Публикация на GitHub Pages

1. Создайте репозиторий, например `username.github.io` (тогда сайт будет
   по адресу `https://username.github.io/`) или любой другой имя
   (`https://username.github.io/имя/`).
2. Из папки этого проекта:

   ```bash
   git init
   git add .
   git commit -m "Портфолио: single-page на Bootstrap 5"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO.git
   git push -u origin main
   ```

3. В GitHub: **Settings → Pages → Source: Deploy from a branch → main / root → Save**.
4. Через минуту сайт откроется по адресу репозитория. Все пути относительные,
   поэтому сайт работает и в корне, и в подпапке. Файл `.nojekyll` отключает
   обработку Jekyll, чтобы папка `_` (если появится) не вырезалась.

Обновление сайта: правите файлы, коммитите, `git push` — Pages перезапустится сам.

## Что заменить на своё (везде пометено комментариями `ЗАМЕНИТЕ`)

- `[Ваше имя]`, `[Имя]` в brand-зоне навбара и футере;
- hero: роль иLead-абзац;
- ссылки соцсетей (`GitHub`, `Telegram`, `Почта`) — удалите лишние пункты;
- фото: блок `.photo-slot` замените на
  `<img src="assets/img/me.jpg" width="480" height="600" alt="...">` (папку `assets/img` создайте сами);
- навыки: проценты в `data-pct` и `style="--p:…"` (держите их одинаковыми);
- опыт и услуги: свои записи, лишние строки удалите;
- работы: плитки-заглушки замените на скриншоты
  `<img src="assets/img/work1.jpg" width="800" height="500" alt="...">` внутри
  `.work-card` и поставьте `href` на живые проекты. Пустые заглушки удалите,
  чтобы не было фейковых кейсов;
- контакты: `[email]` в трёх местах (ссылка, подпись, константа `MAILTO` в
  `assets/js/main.js`), телефон, город;
- заголовок и `<meta description>` в `<head>`.

## Форма на статичном хостинге

GitHub Pages не выполняет серверный код, поэтому форма собирает письмо и
открывает почтовую программу посетителя (`mailto:` с темой и телом). Если
нужна отправка «как на обычном сайте», подключите Formspree: замените у
`<form>` атрибут на `action="https://formspree.io/f/КОД" method="POST"` и
удалите обработчик submit из `assets/js/main.js`.

## Как вернуть секции шаблона

- **Отзывы**: добавляйте только реальные отзывы с именами и должностями
  реальных людей (правило честности: без фейков).
- **Цены**: секция с пакетами уместна для фрилансера — берите пример из
  разметки Knuford, но с настоящими ценами.
- **Блог**: на GitHub Pages проще всего заведение отдельных HTML-страниц
  или переход на Jekyll/Пелкан (тогда уберите `.nojekyll`).

## Глюк «светлое поле справа» после разворачивания окна

Если после максимизации окна или смены масштаба экрана (Параметры →
Дисплей → Масштаб) страница осталась свёрстанной «встарину» — тёмный блок
узже окна, а справа пустое поле цвета фона — это не ошибка вёрстки:
Chrome на Windows иногда не обновляет размеры вьюпорта. Лечится F5,
Ctrl+0, или чуть потянуть окно за край. В `main.js` добавлен пересчёт
высоты hero на `resize` как страховка. Постоянно помогает отказ от
нестандартного пользовательского масштаба (133% и т.п.) в пользу
типовых 100/125/150%.

## Консоль браузера

Откройте `index.html` локально (лучше через любой статический сервер,
например `npx serve .` в этой папке) и проверьте консоль: ошибок быть не должно.
